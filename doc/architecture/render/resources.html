ResourceQueueSet

Since multiple Stage types may run concurrently, and since each Stage may require multiple resources, a greedy resource acquisition policy can fail with deadlock. Instead, a single monitor RQS.M can guard the entire set of resource queues RQS, allowing a consumer to atomically push back on the queue of each needed resource. Mutual waiting is avoided because it only occurs where a group of consumers having overlapping resource needs has been enqeueued with differing precedence on at least two queues of RQS.

ResourceInstance

To avoid limitations on the kinds of resources that can be incorporated into a Stage, a resource interface needs to provide for both passive and active usage models. Active usage occupies the calling thread for the duration of usage, while passive usage can be trivially started, permitting the caller to perform other operations concurrently.
